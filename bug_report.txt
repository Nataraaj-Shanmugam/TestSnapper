FILE: src/background.js
===========================
- Convert to ESM (top-level use of `export` if needed; ensure no globals leak).

- Add Offscreen Document manager for WebLLM host:
  • function ensureOffscreen(): create once via chrome.offscreen.createDocument({ url:'src/webllm-host.html', reasons:['BLOBS'], justification:'Run WebLLM with WebGPU/CPU' })
  • function closeOffscreenWhenIdle(): optional cleanup timer.

- Add message contract handling (listen to runtime.onMessage):
  • 'REC_START'           -> init session state, call ensureOffscreen(), signal LLM init if toggle true.
  • 'REC_STOP'            -> finalize session, flush queues, persist.
  • 'REC_EVENT'           -> accept raw step, pre-enqueue (bounded), schedule batch flush.
  • 'LLM_READY'           -> set llmReady=true; notify popup.
  • 'LLM_ENRICH_BATCH'    -> (from you to offscreen) send; (from offscreen to you) handle results.
  • 'LLM_ENRICH_RESULT'   -> merge enriched text back into steps.
  • 'LLM_PROGRESS'        -> propagate to popup.
  • 'EXPORT_OPEN'         -> chrome.tabs.create({ url:'export_view.html?session=<id>' })
  • 'EXPORT_SAVE'         -> persist edited steps & metadata.
  • 'SCREENSHOT_SAVED'    -> attach image refs.

- Implement per-session queues & batching:
  • Map<sessionId, Step[]> pendingQueue
  • debounce flush (150–250ms)
  • takeBatch(sessionId, N=25)
  • Back-pressure: if offscreen reports BUSY, pause flush; resume on READY.

- Add LRU cache for enrichment:
  • key = hash(`${action}|${normalizedLocator}|${valueKind}|${url}`)
  • If cache hit, skip LLM call, directly fill enriched.

- Persistence:
  • Use chrome.storage.local (or IndexedDB wrapper) with schema:
    { sessions: { [id]: { meta, steps[], network[], shots[] } } }
  • Snapshot large sessions every 200 steps.

- HAR export (MVP):
  • Build minimal HAR JSON from stored network logs.
  • Provide download via chrome.downloads.download(Blob URL).

- Error handling & telemetry:
  • try/catch around message plumbing; bubble {type:'ERROR', code, detail} to popup.
  • Maintain counters: {stepsTotal, stepsEnriched, avgLatencyMs, queueLen}.

FILE: src/webllm-service.js
===========================
- THIS FILE RUNS IN AN OFFSCREEN PAGE (NOT SERVICE WORKER). Load it from webllm-host.html.

- Boot sequence:
  • On load: init() -> CreateMLCEngine with local assets
      const base = chrome.runtime.getURL('assets/webllm/');
      engine = await CreateMLCEngine({ model_id:'qwen2.5-1.5b-q4f32_1', model_url: base });
  • Send {type:'LLM_READY', modelId:'qwen2.5-1.5b'} on success.
  • Emit {type:'LLM_PROGRESS', pct} during model load if API supports it.

- Message handling:
  • onMessage('LLM_ENRICH_BATCH'): for each step -> build compact prompt, call engine.chat.completions.create({ temperature:0.1, max_tokens:32, stop:['\n'] })
  • Sanitize output to one imperative sentence <= 16 words.
  • Return {type:'LLM_ENRICH_RESULT', reqId, results:[{id, enriched}...]}

- Concurrency:
  • Serialize batches or run with small concurrency (2–3 at most) depending on device flag.
  • If WebGPU missing -> set degraded=true; still serve requests via WASM/CPU.

- Caching (optional duplicate guard within this process):
  • Local Map cache keyed by sha1(prompt).

- Robustness:
  • Timeouts per batch (e.g., 10s). On timeout -> return minimal fallback: `${verb} ${shortLocator}`
